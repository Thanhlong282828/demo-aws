## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

| Câu hỏi | Đáp án / kiến thức cần hiểu | Code hoặc lệnh nào? (bấm để mở) | Code / lệnh đó làm gì? |
| --- | --- | --- | --- |
| 1. Vì sao .env không commit? | Vì có thể chứa APP_KEY, DB password và credential riêng theo môi trường. Repo chỉ có .env.example với placeholder; production tạo secret riêng và đặt quyền file phù hợp. | [`.env`](../.gitignore) | Loại môi trường chứa secret khỏi Git. |
| 2. Nếu secret từng commit rồi xóa file thì đã an toàn chưa? | Chưa. Secret có thể còn trong Git history, clone hoặc cache; phải revoke/rotate trước, rồi xử lý history và các bản sao theo phạm vi ảnh hưởng. Thêm gitignore không xóa secret đã được track. | [`.env`](../.gitignore) | Chỉ ngăn theo dõi mới; không xóa secret trong lịch sử, phải thu hồi/đổi secret đã lộ. |
| 3. Vì sao production phải tắt debug? | Debug có thể làm lộ trace, đường dẫn và thông tin nội bộ khi lỗi. APP_DEBUG=false để trả lỗi500 tổng quát cho client; chi tiết phục vụ debug nằm trong log phía server. | [`config('app.debug')`](../bootstrap/app.php) | Ẩn chi tiết exception khi debug tắt. |
| 4. Log dùng để làm gì? | Ghi sự kiện/lỗi để tìm nguyên nhân và đối chiếu thời điểm lỗi, không phải nơi lưu token/password. Mini Shop dùng storage/logs/laravel.log; lỗi web server xem /var/log/nginx/error.log. | [`test_production_error_is_sanitized_and_logged()`](../tests/Feature/Week5ApiTest.php) | Kiểm tra lỗi vẫn được ghi log nhưng response không lộ chi tiết. |
| 5. Validation khác authorization thế nào? | Validation hỏi input có hợp lệ không; authorization hỏi user có được phép thực hiện thao tác không. Giá hợp lệ không làm USER có quyền tạo Product; Admin vẫn bị422 nếu giá âm. | [`rules()`](../Modules/Product/app/Http/Requests/SaveProductRequest.php) | Kiểm input; quyền ADMIN do middleware riêng kiểm tra. |
| 6. N+1 là gì? | Là một query lấy danh sách rồi phát sinh thêm query cho từng item khi đọc relationship. Experiment5 products đọc category bằng lazy loading tạo6 queries:1 Product +5 Category. | [`test_eager_loading_reduces_category_queries()`](../tests/Feature/Week5ApiTest.php) | So số query khi lazy loading với eager loading. |
| 7. Eager loading giúp gì? | Tải relationship trước theo nhóm để giảm query lặp. Product::with(category) trong experiment giảm6 xuống2 queries; đây không phải cam kết mọi endpoint chỉ có2 queries. | [`Product::with('category')`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Tải category cùng danh sách để tránh query theo từng sản phẩm. |
| 8. Pagination giúp gì? | Giới hạn số record của mỗi response để giảm RAM, truy vấn và lượng dữ liệu trả về. Product/Category có per_page tối đa100, mặc định15; Orders cố định15/trang. | [`paginate($data['per_page'] ?? 15)`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Giới hạn dữ liệu mỗi trang; validate per_page tối đa 100. |
| 9. 500 nghĩa gì? | Lỗi ngoài dự kiến phía server khiến request không hoàn thành bình thường. Nó không tự chỉ ra lỗi DB hay PHP; phải xem log và kiểm theo từng lớp. | [`withExceptions(...)`](../bootstrap/app.php) | Định dạng lỗi server thành JSON khi gọi API. |
| 10. Production lỗi nhưng local không lỗi thì bắt đầu kiểm tra gì? | Ghi URL, status và thời điểm, kiểm log Nginx/Laravel/PHP-FPM, sau đó so version source/PHP, env/cache, DB và quyền file. Không bật debug public hoặc paste .env ra chat để tìm lỗi. | [`tail -n 100 storage/logs/laravel.log`](../docs/D34.md) | Đọc lỗi thực tế rồi so PHP, biến môi trường, DB và quyền file. |
