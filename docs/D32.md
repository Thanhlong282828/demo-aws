## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

**Câu 1. Automated test giải quyết vấn đề gì?**

**Đáp án:** Lặp lại kiểm tra bằng code để phát hiện hành vi sai và regression khi sửa project. Suite kiểm response, quyền và dữ liệu sau nghiệp vụ thay vì chỉ nhìn trang có mở được hay không.

**Câu 2. Manual test có còn cần không?**

**Đáp án:** Có. Cần kiểm giao diện, thao tác người dùng và môi trường thật; automated tests chỉ chứng minh những tình huống đã viết. Smoke HTTPS bổ sung bằng chứng Nginx/PHP-FPM/TLS mà feature test local không kiểm hết.

**Câu 3. Feature test là gì ở mức em hiểu?**

**Đáp án:** Là test hành vi một tính năng qua nhiều thành phần, thường gửi request vào Laravel kernel rồi assert status/JSON/database. Nó rộng hơn test một hàm đơn lẻ và không nhất thiết mở trình duyệt thật.

**Câu 4. Regression là gì?**

**Đáp án:** Là chức năng trước đây hoạt động bị hỏng sau thay đổi. Experiment của project bỏ GET Product index làm test FAIL405; khôi phục route thì test PASS.

**Câu 5. Chỉ test happy path đã đủ chưa?**

**Đáp án:** Chưa. Cần cả dữ liệu sai, user thiếu quyền, tài nguyên không có và lỗi giữa transaction; nếu chỉ test Admin tạo Product hợp lệ thì có thể bỏ sót Guest/User ghi trái phép.

**Câu 6. Authorization có đáng test không?**

**Đáp án:** Có vì sai quyền có thể làm lộ đơn hàng hoặc cho phép sửa dữ liệu trái phép. Test USER→Admin API, Guest→protected API và User A→Order B có giá trị cao.

**Câu 7. Validation có đáng test không?**

**Đáp án:** Có vì input sai có thể phá quy tắc DB/nghiệp vụ. Ví dụ test price âm, stock âm và category không tồn tại nhận422, đồng thời không tạo Product sai.

**Câu 8. Checkout transaction có đáng test không?**

**Đáp án:** Rất đáng vì liên quan order/items/stock/cart/coupon cùng lúc. Test ném lỗi ở item thứ2 để xác nhận tất cả thay đổi trước đó rollback, không trừ tồn hoặc tạo đơn nửa chừng.

**Câu 9. Test fail có nghĩa implementation chắc chắn sai không?**

**Đáp án:** Không. Có thể implementation sai, expectation sai, fixture sai hoặc môi trường/DB bị lỗi. Đọc assertion và log, đối chiếu requirement; không sửa code chỉ để chiều một test có kỳ vọng sai.

**Câu 10. 100% coverage có đồng nghĩa app không bug không?**

**Đáp án:** Không. Coverage đo code được chạy qua, không chứng minh dữ liệu/assertion đủ hoặc mọi business rule đúng. Project ưu tiên flow có rủi ro, không tuyên bố100% coverage.
