# D30 — Authentication + Authorization

## Học gì?

Phân biệt ai đang gọi với được làm gì; token hash/expire/revoke, role và ownership.

## Tự làm theo source

Đọc bảng từ trên xuống. Bấm vào tên file để mở source, tìm hàm/đoạn code được mô tả ở cột bên phải.

| File cần mở | Code cần đọc và nhiệm vụ của code |
| --- | --- |
| [app/Http/Controllers/Api/AuthController.php](../app/Http/Controllers/Api/AuthController.php) | Tự validate credentials, Hash::check, tạo token 8h; không invent JWT. Logout revoke token hiện tại. |
| [app/Models/User.php](../app/Models/User.php) | HasApiTokens là trait của Sanctum. |
| [Modules/Shop/app/Http/Middleware/Admin.php](../Modules/Shop/app/Http/Middleware/Admin.php) | So role ADMIN ở server trước controller. |
| [Modules/Shop/app/Http/Controllers/Api/OrderController.php](../Modules/Shop/app/Http/Controllers/Api/OrderController.php) | So chủ đơn với authenticated user, không nhận owner từ body. |

Đọc lần lượt, tự gõ lại phần thay đổi trên branch luyện tập; gửi request hoặc chạy test sau từng bước. Controller không tin role/user_id/total từ client. Đối chiếu response với [API docs](api.md).

## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

| Câu hỏi | Trả lời | Code nào → làm gì? |
| --- | --- | --- |
| 1. 401 và 403 khác nhau thế nào? | 401: chưa xác thực được, như thiếu token, token hết hạn hoặc<br>login sai. 403: đã xác thực nhưng không được phép, như USER<br>xóa Product hoặc xem đơn người khác. | [`middleware('auth:sanctum')`](../Modules/Shop/routes/api.php)<br>→ Kiểm tra đăng nhập<br>Admin middleware kiểm tra quyền riêng. |
| 2.<br>Authentication và Authorization khác<br>nhau thế nào? | Authentication xác định người gọi là ai<br>Authorization xác định người đó được làm gì với tài nguyên.<br>auth:sanctum kiểm token<br>Admin middleware và kiểm owner xử lý quyền. | [`$request->user()?->role === 'ADMIN'`](../Modules/Shop/app/Http/Middleware/Admin.php)<br>→ Chỉ tài khoản ADMIN được qua middleware. |
| 3.<br>API token dùng để làm gì? | Client gửi token trong Authorization: Bearer để server nhận<br>diện user cho request được bảo vệ.<br>Sanctum hash token trong DB<br>project cấp hạn8 giờ và có endpoint revoke token. | [`createToken('postman', ['*'], now()->addHours(8))`](../app/Http/Controllers/Api/AuthController.php)<br>→ Cấp Bearer token hết hạn sau 8 giờ. |
| 4.<br>Token có nên commit GitHub không? | Không.<br>Token có thể cho phép người khác hành động dưới danh tính<br>tài khoản<br>để token ở giá trị environment local/private và để rỗng khi<br>export collection.<br>Nếu đã lộ phải revoke/rotate. | [`token = ""`](../docs/postman/local.postman_environment.json)<br>→ Export môi trường với token trống, tránh công<br>khai token thật. |
| 5.<br>Public endpoint là gì? | Endpoint cho phép gọi mà không cần đăng nhập.<br>Ví dụ GET Product/Category, nhưng vẫn cần validation,<br>pagination và xử lý lỗi. | [`only(['index', 'show'])`](../Modules/Product/routes/api.php)<br>→ Cho phép đọc sản phẩm không cần token. |
| 6.<br>Protected endpoint là gì? | Endpoint yêu cầu authentication, có thể kèm role hoặc<br>ownership.<br>Ví dụ GET /api/orders yêu cầu token<br>POST Product còn yêu cầu role ADMIN. | [`middleware('auth:sanctum')`](../Modules/Shop/routes/api.php)<br>→ Bảo vệ orders/logout bằng token. |
| 7.<br>Normal User gọi Admin API phải trả gì? | User có token hợp lệ nhưng role USER phải nhận403.<br>Nếu thiếu token hoặc token không hợp lệ thì401, không đi<br>thẳng vào controller ghi dữ liệu. | [`abort_unless(..., 403)`](../Modules/Shop/app/Http/Middleware/Admin.php)<br>→ Chặn user thường khỏi API admin. |
| 8.<br>User A xem Order của B là<br>authentication hay authorization<br>problem? | Là authorization, cụ thể ownership: A đã được xác thực nhưng<br>không sở hữu đơn B.<br>Controller so order.user_id với authenticated user.id và<br>trả403 khi không khớp. | [`show()`](../Modules/Shop/app/Http/Controllers/Api/OrderController.php)<br>`abort_unless(...)`<br>→ So chủ đơn hàng với user đang gọi, chặn truy cập<br>đơn người khác. |
| 9.<br>HTTPS liên quan token thế nào ở mức cơ<br>bản? | HTTPS mã hóa và kiểm tra tính toàn vẹn kết nối, đồng thời<br>xác thực máy chủ qua chứng chỉ<br>giúp bảo vệ token trên đường truyền.<br>HTTPS không thay thế role/owner check và không bảo vệ token<br>bị lộ trong log/source. | [`Nginx HTTPS / TLS`](../docs/D34.md)<br>→ Mã hóa đường truyền mang Bearer token<br>đây là cấu hình VPS. |
| 10.<br>Hide endpoint khỏi frontend có bảo vệ<br>API không? | Không.<br>Người dùng vẫn có thể gửi request trực tiếp bằng<br>curl/Postman<br>backend phải tự kiểm authentication, authorization và<br>validation ở mỗi endpoint. | [`middleware(Admin::class)`](../Modules/Shop/routes/api.php)<br>→ Kiểm quyền tại server dù client tự gửi request. |
