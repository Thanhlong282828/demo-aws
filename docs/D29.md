# D29 — REST API Product

## Học gì?

Hiểu Route → Controller → Model → Resource → JSON; HTTP method, URL và status. Web controller trả Blade, API controller trả JSON.

## Tự làm theo source

Đọc bảng từ trên xuống. Bấm vào tên file để mở source, tìm hàm/đoạn code được mô tả ở cột bên phải.

| File cần mở | Code cần đọc và nhiệm vụ của code |
| --- | --- |
| [Modules/Product/routes/api.php](../Modules/Product/routes/api.php) | Đọc apiResource: index/show public; write qua auth:sanctum + Admin. |
| [Modules/Product/app/Http/Controllers/Api/ProductController.php](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Tự viết index với with(category), validate per_page, paginate; show model binding; store/update dùng validated(); destroy trả data:null. |
| [Modules/Product/app/Http/Requests/SaveProductRequest.php](../Modules/Product/app/Http/Requests/SaveProductRequest.php) | Áp dụng rule giá, stock, category tồn tại. |
| [app/Http/Resources/ProductResource.php](../app/Http/Resources/ProductResource.php) | Chỉ expose contract cần thiết, không serialize model tùy tiện. |

Đọc lần lượt, tự gõ lại phần thay đổi trên branch luyện tập; gửi request hoặc chạy test sau từng bước. Controller không tin role/user_id/total từ client. Đối chiếu response với [API docs](api.md).

## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

| Câu hỏi | Đáp án / kiến thức cần hiểu | Code hoặc lệnh nào? (bấm để mở) | Code / lệnh đó làm gì? |
| --- | --- | --- | --- |
| 1. API giải quyết vấn đề gì? | API cung cấp giao diện để client giao tiếp với backend theo contract rõ ràng, ví dụ ứng dụng mobile lấy danh sách sản phẩm mà không cần đọc HTML. | [`index()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Đọc sản phẩm để client nhận dữ liệu. |
| 2. JSON khác HTML response thế nào? | JSON biểu diễn dữ liệu có cấu trúc cho chương trình xử lý; HTML mô tả nội dung và cấu trúc trang web. API Product trả JSON qua Resource; web Product trả Blade/HTML. | [`toArray()`](../app/Http/Resources/ProductResource.php) | Chọn trường trả về trong JSON. |
| 3. GET dùng khi nào? | Dùng để đọc dữ liệu và không chủ ý thay đổi trạng thái nghiệp vụ, ví dụ GET /api/products hoặc GET /api/products/5. | [`index() / show()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Đọc danh sách hoặc một sản phẩm. |
| 4. POST dùng khi nào? | Dùng để tạo tài nguyên hoặc yêu cầu xử lý một thao tác. POST /api/products tạo sản phẩm; POST /api/login xác thực và cấp token. | [`store() → Product::create($request->validated())`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Tạo sản phẩm từ input đã kiểm tra. |
| 5. PUT và PATCH dùng khi nào? | PUT thường biểu diễn thay thế toàn bộ trạng thái tài nguyên; PATCH sửa một phần. Riêng project hiện tại, cả PUT/PATCH Product dùng cùng SaveProductRequest nên đều phải gửi đủ các trường required; chưa hỗ trợ sparse PATCH. | [`update() → $product->update($request->validated())`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Cập nhật sản phẩm được route binding tìm thấy. |
| 6. DELETE dùng khi nào? | Dùng để xóa tài nguyên xác định bởi URL, ví dụ DELETE /api/products/5. Server vẫn phải kiểm token, quyền Admin và quy tắc liên quan trước khi xóa. | [`destroy() → $product->delete()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Xóa sản phẩm, trả thông báo JSON. |
| 7. 200 có nghĩa gì? | Request đã xử lý thành công. Project dùng 200 cho GET, update và delete có JSON body; không dùng 200 để che lỗi resource không tồn tại. | [`destroy() → response()->json(...)`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Trả JSON thành công; status mặc định 200. |
| 8. 201 có nghĩa gì? | Request đã tạo tài nguyên mới thành công, ví dụ Admin POST Product hợp lệ. Response chứa data của sản phẩm vừa lưu, có id mới. | [`store() → setStatusCode(201)`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Báo đã tạo tài nguyên mới. |
| 9. 404 có nghĩa gì? | Không tìm thấy tài nguyên hoặc route được yêu cầu. Ví dụ Product id không có trong MySQL thì model binding trả 404, không trả 200 kèm chuỗi lỗi. | [`show(Product $product)`](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Model binding tìm theo ID; Laravel trả 404 khi không có. |
| 10. 422 có nghĩa gì? | Server hiểu request nhưng dữ liệu không đạt validation hoặc quy tắc nghiệp vụ. Ví dụ price âm, category_id không tồn tại hoặc status chuyển sai; JSON errors chỉ ra trường cần sửa. | [`rules()`](../Modules/Product/app/Http/Requests/SaveProductRequest.php) | Khai báo điều kiện input; vi phạm trả 422. |
| 11. URL /api/products/5 chứa thông tin gì? | /api/products là collection Product; 5 là định danh tài nguyên cần xử lý. HTTP method mới xác định đọc, sửa hay xóa; id trong URL không cấp quyền cho người gọi. | [`Route::apiResource('products', ProductController::class)`](../Modules/Product/routes/api.php) | Ánh xạ URL chứa ID sang action show/update/destroy. |
| 12. API client có nhất thiết phải là browser không? | Không. Client có thể là Postman, curl, ứng dụng mobile, frontend JavaScript hoặc backend khác gửi HTTP request đúng contract. | [`request`](../docs/postman/Mini-Shop-API.postman_collection.json) | Lưu HTTP request để gọi API qua Postman. |
