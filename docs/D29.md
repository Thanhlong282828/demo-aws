# D29 — REST API Product

## Học gì?

Hiểu Route → Controller → Model → Resource → JSON; HTTP method, URL và status. Web controller trả Blade, API controller trả JSON.

## Tự làm theo source

Đọc bảng từ trên xuống. Bấm vào tên file để mở source, tìm hàm/đoạn code được mô tả ở cột bên phải.

| File cần mở                                                                                                                         | Code cần đọc và nhiệm vụ của code                                                                                                        |
| ----------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| [Modules/Product/routes/api.php](../Modules/Product/routes/api.php)                                                                 | Đọc apiResource: index/show public; write qua auth:sanctum + Admin.                                                                      |
| [Modules/Product/app/Http/Controllers/Api/ProductController.php](../Modules/Product/app/Http/Controllers/Api/ProductController.php) | Tự viết index với with(category), validate per_page, paginate; show model binding; store/update dùng validated(); destroy trả data:null. |
| [Modules/Product/app/Http/Requests/SaveProductRequest.php](../Modules/Product/app/Http/Requests/SaveProductRequest.php)             | Áp dụng rule giá, stock, category tồn tại.                                                                                               |
| [app/Http/Resources/ProductResource.php](../app/Http/Resources/ProductResource.php)                                                 | Chỉ expose contract cần thiết, không serialize model tùy tiện.                                                                           |

Đọc lần lượt, tự gõ lại phần thay đổi trên branch luyện tập; gửi request hoặc chạy test sau từng bước. Controller không tin role/user_id/total từ client. Đối chiếu response với [API docs](api.md).

## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

| Câu hỏi                                                   | Trả lời                                                                                                                                                                                                                                 | Code nào → làm gì?                                                                                                                                                               |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1.<br>API giải quyết vấn đề gì?                           | API cung cấp giao diện để client giao tiếp với backend theo<br>contract rõ ràng, ví dụ ứng dụng mobile lấy danh sách sản<br>phẩm mà không cần đọc HTML.                                                                                 | [`index()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>→ Đọc sản phẩm để client nhận dữ liệu.                                                         |
| 2.<br>JSON khác HTML response thế nào?                    | JSON biểu diễn dữ liệu có cấu trúc cho chương trình xử lý<br>HTML mô tả nội dung và cấu trúc trang web.<br>API Product trả JSON qua Resource<br>web Product trả Blade/HTML.                                                             | [`toArray()`](../app/Http/Resources/ProductResource.php)<br>→ Chọn trường trả về trong JSON.                                                                                     |
| 3.<br>GET dùng khi nào?                                   | Dùng để đọc dữ liệu và không chủ ý thay đổi trạng thái<br>nghiệp vụ, ví dụ GET /api/products hoặc GET /api/products/5.                                                                                                                  | [`index() / show()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>→ Đọc danh sách hoặc một sản phẩm.                                                    |
| 4.<br>POST dùng khi nào?                                  | Dùng để tạo tài nguyên hoặc yêu cầu xử lý một thao tác.<br>POST /api/products tạo sản phẩm<br>POST /api/login xác thực và cấp token.                                                                                                    | [`store()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>`Product::create($request->validated())`<br>→ Tạo sản phẩm từ input đã kiểm tra.               |
| 5.<br>PUT và PATCH dùng khi nào?                          | PUT thường biểu diễn thay thế toàn bộ trạng thái tài nguyên<br>PATCH sửa một phần.<br>Riêng project hiện tại, cả PUT/PATCH Product dùng cùng<br>SaveProductRequest nên đều phải gửi đủ các trường required<br>chưa hỗ trợ sparse PATCH. | [`update()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>`$product->update($request->validated())`<br>→ Cập nhật sản phẩm được route binding tìm thấy. |
| 6.<br>DELETE dùng khi nào?                                | Dùng để xóa tài nguyên xác định bởi URL, ví dụ DELETE<br>/api/products/5.<br>Server vẫn phải kiểm token, quyền Admin và quy tắc liên quan<br>trước khi xóa.                                                                             | [`destroy()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>`$product->delete()`<br>→ Xóa sản phẩm, trả thông báo JSON.                                  |
| 7. 200 có nghĩa gì?                                       | Request đã xử lý thành công.<br>Project dùng 200 cho GET, update và delete có JSON body<br>không dùng 200 để che lỗi resource không tồn tại.                                                                                            | [`destroy()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>`response()->json(...)`<br>→ Trả JSON thành công<br>status mặc định 200.                     |
| 8. 201 có nghĩa gì?                                       | Request đã tạo tài nguyên mới thành công, ví dụ Admin POST<br>Product hợp lệ.<br>Response chứa data của sản phẩm vừa lưu, có id mới.                                                                                                    | [`store()`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>`setStatusCode(201)`<br>→ Báo đã tạo tài nguyên mới.                                           |
| 9. 404 có nghĩa gì?                                       | Không tìm thấy tài nguyên hoặc route được yêu cầu.<br>Ví dụ Product id không có trong MySQL thì model binding trả<br>404, không trả 200 kèm chuỗi lỗi.                                                                                  | [`show(Product $product)`](../Modules/Product/app/Http/Controllers/Api/ProductController.php)<br>→ Model binding tìm theo ID<br>Laravel trả 404 khi không có.                    |
| 10. 422 có nghĩa gì?                                      | Server hiểu request nhưng dữ liệu không đạt validation hoặc<br>quy tắc nghiệp vụ.<br>Ví dụ price âm, category_id không tồn tại hoặc status chuyển<br>sai<br>JSON errors chỉ ra trường cần sửa.                                          | [`rules()`](../Modules/Product/app/Http/Requests/SaveProductRequest.php)<br>→ Khai báo điều kiện input<br>vi phạm trả 422.                                                       |
| 11.<br>URL /api/products/5 chứa thông tin gì?             | /api/products là collection Product<br>5 là định danh tài nguyên cần xử lý.<br>HTTP method mới xác định đọc, sửa hay xóa<br>id trong URL không cấp quyền cho người gọi.                                                                 | [`Route::apiResource('products', ProductController::class)`](../Modules/Product/routes/api.php)<br>→ Ánh xạ URL chứa ID sang action<br>show/update/destroy.                      |
| 12.<br>API client có nhất thiết phải là<br>browser không? | Không.<br>Client có thể là Postman, curl, ứng dụng mobile, frontend<br>JavaScript hoặc backend khác gửi HTTP request đúng contract.                                                                                                     | [`request`](../docs/postman/Mini-Shop-API.postman_collection.json)<br>→ Lưu HTTP request để gọi API qua Postman.                                                                 |
