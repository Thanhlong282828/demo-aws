## Câu hỏi kiến thức và đáp án tham khảo

Cách học: tự trả lời trước, sau đó đối chiếu đáp án và source. Đáp án để ôn tập, không chứng nhận bạn đã tự làm hoặc đã đạt điểm.

**Câu 1. API giải quyết vấn đề gì?**

**Đáp án:** API cung cấp giao diện để client giao tiếp với backend theo contract rõ ràng, ví dụ ứng dụng mobile lấy danh sách sản phẩm mà không cần đọc HTML.

**Câu 2. JSON khác HTML response thế nào?**

**Đáp án:** JSON biểu diễn dữ liệu có cấu trúc cho chương trình xử lý; HTML mô tả nội dung và cấu trúc trang web. API Product trả JSON qua Resource; web Product trả Blade/HTML.

**Câu 3. GET dùng khi nào?**

**Đáp án:** Dùng để đọc dữ liệu và không chủ ý thay đổi trạng thái nghiệp vụ, ví dụ GET /api/products hoặc GET /api/products/5.

**Câu 4. POST dùng khi nào?**

**Đáp án:** Dùng để tạo tài nguyên hoặc yêu cầu xử lý một thao tác. POST /api/products tạo sản phẩm; POST /api/login xác thực và cấp token.

**Câu 5. PUT và PATCH dùng khi nào?**

**Đáp án:** PUT thường biểu diễn thay thế toàn bộ trạng thái tài nguyên; PATCH sửa một phần. Riêng project hiện tại, cả PUT/PATCH Product dùng cùng SaveProductRequest nên đều phải gửi đủ các trường required; chưa hỗ trợ sparse PATCH.

**Câu 6. DELETE dùng khi nào?**

**Đáp án:** Dùng để xóa tài nguyên xác định bởi URL, ví dụ DELETE /api/products/5. Server vẫn phải kiểm token, quyền Admin và quy tắc liên quan trước khi xóa.

**Câu 7. 200 có nghĩa gì?**

**Đáp án:** Request đã xử lý thành công. Project dùng 200 cho GET, update và delete có JSON body; không dùng 200 để che lỗi resource không tồn tại.

**Câu 8. 201 có nghĩa gì?**

**Đáp án:** Request đã tạo tài nguyên mới thành công, ví dụ Admin POST Product hợp lệ. Response chứa data của sản phẩm vừa lưu, có id mới.

**Câu 9. 404 có nghĩa gì?**

**Đáp án:** Không tìm thấy tài nguyên hoặc route được yêu cầu. Ví dụ Product id không có trong MySQL thì model binding trả 404, không trả 200 kèm chuỗi lỗi.

**Câu 10. 422 có nghĩa gì?**

**Đáp án:** Server hiểu request nhưng dữ liệu không đạt validation hoặc quy tắc nghiệp vụ. Ví dụ price âm, category_id không tồn tại hoặc status chuyển sai; JSON errors chỉ ra trường cần sửa.

**Câu 11. URL /api/products/5 chứa thông tin gì?**

**Đáp án:** /api/products là collection Product; 5 là định danh tài nguyên cần xử lý. HTTP method mới xác định đọc, sửa hay xóa; id trong URL không cấp quyền cho người gọi.

**Câu 12. API client có nhất thiết phải là browser không?**

**Đáp án:** Không. Client có thể là Postman, curl, ứng dụng mobile, frontend JavaScript hoặc backend khác gửi HTTP request đúng contract.
